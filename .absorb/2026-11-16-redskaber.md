## 4. blocked

无。C1–C7 均可在本地现有 flake-parts / nix-unit / sops 结构内分阶段落地；C6 有 secrets 迁移风险，但采用「先加 host 收件人、保留 user key、逐 host 验证后再移除」的过渡路径，不构成 blocked。

## 5. 一句话结论

最值得抄的两件事：**用 nix-unit / 纯 eval 契约测试把 HM dotfile 与模块 enable 减法语义钉住**（C3+C4，直接补本地 101 个 HM 模块、72 个 NixOS 模块的测试空白，且不需要 QEMU），以及**模块可达性仓库卫生门**（C2，flake-parts + scanPaths 下死目录对所有现有闸门不可见）。目标 repo 的测试成熟度是「强」（108 tests + 6 道卫生门），但其 QEMU 平面和 10 阶段 CI 是为 5 平台/114 checks 规模服务的，本地应只吸收「纯 eval 层」与「注册表/审计」两件内核，不复制 VM 与矩阵成本。

## 规范摩擦点

1. **模板与 struct 不一致**：`output.struct` 的候选字段含「状态」，但 `output.template` 的候选表头没有「状态」列；本报告按 struct 补了该列。建议模板同步。
2. **30 文件精读上限与 focus=D4 冲突**：测试成熟度强的 repo，仅 `tests/default.nix` + 6 道卫生门 + nmt harness + CI 就要 20+ 文件，再加 flake/入口/模块抽样会顶到上限；建议 focus 命中时把上限提到 40 或允许「tests/ 目录按门计数」。
3. **pin 规则未覆盖「声明 ref 与 lock.original.ref 不一致」**：规范只要求「有 lock 记 rev / 无 lock 记声明 ref」，但目标正是 flake.nix 声明 `nixos-26.05` 而 lock 的 `original.ref` 仍是 `nixos-unstable` 且 rev 停在半年前；本报告按「lock rev + 声明漂移」双记，建议规范明确此类如何定级（是记录差距还是直接标 blocked）。
4. **本地锚定假设了固定目录名**：gate 要求读本地 `modules/`、`outputs/` 等，但 flake-parts 仓库的模块路由在 `outputs/` 与 perSystem，`modules/` 可能只是部分模块；建议 gate 注明「flake-parts 以 outputs/ + lib/ 为等价物」，避免把架构差异误判为能力缺失。
