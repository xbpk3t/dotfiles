## 5. 一句话结论

这个 repo 的 Determinate 质量工具链在 CI 里基本没有启用（DeterminateCI `if: false`，flakeaudit/flakebom 只是桌面包），真正值得抄的是它对 GitHub Actions 的供应链策略（zizmor 白名单 + SHA pin + `persist-credentials: false` + dependabot cooldown），以及 macOS 侧对 Rust target 目录的 CACHEDIR.TAG 精确清理；其余维度本地均更成熟。

## 规范摩擦点

- **F1（D1 术语与可获取性）**：`absorb.yml:37` 把 flakeaudit / flakebom / secure-build 列为通用质量闸门术语，但没有提示先验证工具是否公开可用。实际它们属于 Determinate Secure Packages 付费/私有能力，导致 C4 只能 blocked；如果按“照抄工具链”的思路写候选，会产出无法落地的建议。建议在 D1 增加一句“先确认 input/工具的可获取性，再决定候选”。
