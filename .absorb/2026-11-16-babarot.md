## 5. 一句话结论

最值得抄的是 **C3：把 shell 分成 `is_human` 的人类 UX 与 agent 的 plain zsh**——本地 agent 现在会继承 `cat=bat`/`find=fd`/`grep=rg` 和 `EDITOR=hx`，这是真实的行为风险；其次是 **C4：用 `mkOutOfStoreSymlink` 把手写配置指回 repo**，本地 `.hammerspoon` 已有意图但写法仍是 in-store。安全上 **C2 的 CA 黑名单** 成本最低、应立刻做。

## 规范摩擦点

| id | 摩擦点（现象 / 卡住的位置） | 建议改法（加/删/改） | 理由 |
|----|--------------------------|---------------------|------|
| F1 | 抽样阈值写“文件数 >200”，未区分 `.nix` 文件与总文件。本次目标只有 106 个 `.nix`/4191 行，但全仓 260 个文件（docs、lua、patch），按字面触发 30 个精读上限；按 nix 行数其实远未到 5000。 | 改 constraint：`nix 文件数 >200 或 nix 总行数 >5000`；全仓文件数只用于“是否全量通读”的辅助判断。 | 阈值目的是控制阅读量，不是控制资源文件数量；否则 docs/图片多的 repo 会被误判为大 repo。 |
| F2 | `output.struct` 列了 `架构摘要`，但 `template` 没有对应小节（只有“锚定”和“本地已有能力”）。执行者只能把架构摘要塞进“锚定”的 bullet，结构化字段和模板对不上。 | 改 template：在 `## 0. 锚定` 下加一行 `- 架构摘要：...`，或单独加 `### 架构摘要`；output.struct 与 template 保持同名。 | 模板是执行者唯一可机械照抄的结构；struct 和 template 不一致会导致不同 sub-agent 产出不可比。 |
| F3 | D3 写“目标只有单平台内嵌 HM 时，只评组织与 secret 注入”，但 target 是单平台 **nix-darwin + standalone HM**（不是 NixOS 内嵌），且完全没有 secret 进 Nix；“secret 注入”子项无内容可评。 | 改 D3：写成“目标为单平台（NixOS 或 nix-darwin）内嵌/独立 HM 时，只评组织与 dotfile 处理；无 Nix 内 secret 时，D5 记录‘secret 在 Nix 外’并跳过注入边界”。 | 避免执行者为了填“secret 注入”硬找内容，也避免把 nix-darwin HM 误判成不符合“内嵌 HM”前提。 |
| F4 | 候选表要求 P1 以上“验证方式”，但 D7 文档类候选（根 AGENTS.md）只能给“agent 行为观察”这类非命令验证，模板没有说明这类验证可接受什么形式。 | 在 phase 2 加一句：文档/流程类候选可用“文件存在 + 链接可达 + 一次 agent 任务观察”作为验证，不强制命令。 | 否则执行者要么编命令，要么把高价值文档候选降级成 P2。 |
