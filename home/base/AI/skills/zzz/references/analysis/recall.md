# recall — 闭卷召回

闭卷出题 → 你作答 → 批改打分 → 主动问是否需要【类比】/【mapping】/就 gap【展开】；未明确同意前禁止输出后三项正文。

---

## 1. 出题

- 每轮优先 **1** 题；你明确要求多题再多抛（可一次 A/B/C…，但批改仍逐题）。
- **禁止**先讲、先搜答案、先贴 mdscc / 标准答案全文。
- 题源：当前讨论的 topic、`data/gh` 的 `qs` / `ww` / 3w3h 条目、或你指定的范围。
- 有 topic 上下文时标明来源（如「来自 ww」「来自 qs」）；声明建议的 **主 role**（只给 role 词，不泄露答案要点）。

发出题面后附答题格式，然后 **停止等待**。

### 答题格式（你按此交卷）

```text
role: meta | derive | sol | cost | case | l3
上挂: <topic>（<kind>）——该停在哪一层
闭卷-meta: （该 topic 的元问题，一句；可全 topic 共用同一句）
闭卷-本题: （直接回答题面）
可选-maps: （一句异层同构；不会就写「无」或「想知道」）
```

### role 规则

- **主 role 用 mdscc：** `meta | derive | sol | cost | case | l3`
- **3w3h**（what/hti/htu…）只作 **副标签**，不能代替主 role
  例：题练实现谱系 → `role: sol`（副 hti）；题练概念拆解 → `role: derive`（副 what）
- `l3` = 跨挂 / maps 向；**L3 surface**（题面是 ops/CLI/监控）由题面判定：批改时 **禁止**建议改 `mdscc.meta`

### meta 规则

- **topic 级 meta 全 topic 共用一条**（方向例：并发 + 一致快照 + 少阻塞），不是每道 qs 各写一条 mdscc.meta。
- 练习时每题仍建议带一行 `闭卷-meta`（可复制同一句）——强迫先上挂再答题。
- qs **没有**自己的 mdscc.meta；「这题练骨架哪一刀」= role，不是第二条元问题。
- meta 必须是 **一句** 第一性原理式问题；禁止 FAQ / 步骤 / 监控清单。

## 2. 批改

仅在你交卷后进行。可轻量核对硬事实；网络不可用则标 offline，不挡批改。

### 分数

| 分 | 含义 |
|----|------|
| **0** | 方向错、当 FAQ/清单、零关键词、或空白（诚实空白仍 0，语气建设性） |
| **1** | 方向有，但与骨架/题面错位、**绝对化**、漏题面关键词 |
| **2** | 主 role 合理 + 贴 meta 精神 + 本题答在点上（maps 加分不替代本题完整度） |

### 必查

- **上挂仪式**：有没有挂到对的 topic/层（可共用 meta，不扣「重复五遍」）
- **role**：是否 mdscc 主 role；3w3h 仅副
- **case 绝对化**：禁止「凡 XX 品类都要/都不要」式全家桶；应用 **需求语言**（要不要多读者稳定视图、读写并发、事务快照）
- **题面关键词是否答全**（例：问了间隙锁就不能只答 ReadView）
- **过满表述**：如把 MVCC 说成「高并发强一致」、把「热点/秒杀」说成「不该上 MVCC」——方向半对也要降分并点破
- 骨架建议最多口头一句；**默认不写** `data/gh` / wiki

### 批改输出（聊天内即可）

逐题：role 是否合理、meta/上挂、本题是否贴题面与骨架、maps 质量、**分 0/1/2**、一行 gap。
多题给总分表 + 本轮习惯结论（例：case 易绝对化、硬机制题要对准关键词、maps 要主动写）。

你写 maps「不知道/想知道」时：在批改里 **可以先给一句合格 maps 供对照**（仍算批改的一部分）；若要展开成多条同构或类比表，必须先走第 3 步询问。

## 3. 询问（批改后必做）

批改输出后 **必须**问（可多选；默认都不做）：

1. 是否需要 **【类比】**（跨域生活隐喻，助记）？
2. 是否需要 **【mapping】**（异层同构，步骤级对应）？
3. 是否需要就 **gap** 做简短 **【展开】**？

## 4. 类比（仅当你同意）

**是什么：** 跨域、偏生活的隐喻，降低记忆成本。
**不是：** 异层同构、相关 topic 列表（那是 mapping）。

### 输出格式（1–3 条，针对本题 gap / 核心概念现写）

```text
概念：…
类比：…
对应：类比里的 X = 技术里的 Y
```

### 风格参考（搬自原 tech-anoloy；示例不是题库，空项勿瞎补）

- 高可用：有很多备胎，即使失恋了，也可以迅速和别人谈恋爱
- 注册中心：民政局
- 负载均衡：和多个女朋友轮流约会
- API 网关：相亲前的介绍人，双方无法直接联系，由介绍人代传
- 同步和异步：同步就是一次只和一个女朋友约会，异步就是和多个女朋友约会
- 异步线程不安全：一次和多个女朋友约会，很不安全
- 分布式锁：同时和多个女朋友约会，要时间管理，否则会冲突
- 分布式缓存：房间直接开一个月的，每次约会直接去，不需要每次都再开
- 分布式消息队列：炮友，约就来，结束后主动离开，不约就不来
- 分布式事务：离婚后很痛苦，希望没和她结过婚、没生孩子，一切回到婚前的样子——所以分布式事务很难
- 异地多活：出差到任何城市，都有炮友
- 广播调用：同时向多个女朋友求婚，谁先答应就和谁结婚

按本题写新类比时，保持同级「土、好记、一句钉死对应」；不要写成论文定义。

## 5. mapping（仅当你同意；答卷里也可先写一句）

**是什么：异层同构**——在另一抽象层（业务代码 / 应用协议 / VCS / 运行时调度…）找到与本题 **同一套控制结构**，并写出 **步骤或判定的一一对应**，用来迁移理解。

**不是：** 目录邻接、depends-on 图谱、「和 X 有关」的词条列表、生活段子（段子走类比）。

### 输出格式

一句也可以；展开时用：

```text
本题结构：…
另一层：…
对应：
  - （本题）… ↔ （另一层）…
  - …
可迁移判断：…
```

### 合格 / 不合格（必须按此校准）

**合格（来自真实召回，应模仿的密度与形状）：**

1. **MVCC 可见性 ↔ 业务「一锁二判三更新」**（canonical）
   - 本题：版本链 + ReadView；用 trx_id 与高低水位比较决定可见版本；提交前冲突则失败。
   - 另一层：高并发业务先读 version → 判断 → 再更新；失败则 spin / for 重试。
   - 同构：先基于某一视图做判断，再提交变更；冲突则重来——不是「都和并发有关」。

2. **普通 SELECT（快照读）↔ git log / checkout 看历史提交**
   - 已有提交视图不被后来 push 改掉 ≈ 快照内多次读稳定。
   - 可迁移：版本/快照管 **读一致**。

3. **`SELECT … FOR UPDATE` + 间隙/临键 ↔ protected branch / MR 门禁**
   - 锁范围、防「范围内新插入」≈ 禁止往保护分支直接塞新提交。
   - 可迁移：锁管 **写与范围保护**；与快照读分职。
   - 注意：git 没有真 gap lock，类比到「保护范围」即可，不必抠死。

4. **MVOCC vs MV2PL ↔ 乐观锁 vs 悲观锁**
   - 更乐观：先做事、提交 validation，失败 **abort**。
   - 更悲观：先锁，**delay** 等待；死锁则 abort 一方。
   - 可迁移：delay 谱系 vs abort 谱系。

5. **CC 的 delay/abort ↔ 线程同步里阻塞 vs 失败重试**
   - 调度语义同构，不是「CC 和操作系统都是系统软件」。

6. **何时需要多版本事务语义 ↔ 协作文档快照 / COW**
   - 需要：多读者要稳定视图、读写并发。
   - 不需要：单写者队列、只追加日志、覆盖写且无事务读。
   - 用 **需求** 说话，不用「凡 KV/文档库都要 MVCC」品类全家桶。

7. **应用层 version 字段**
   - 有一点多版本/乐观并发味道，但是 **应用层**；库仍可能行锁、无经典 MVCC——maps 时分层说清。

**不合格：**

- 「maps：和隔离级别有关 / 见 RDB 其它 topic」→ 目录邻接
- 「凡 NewSQL/缓存都要 MVCC」→ 品类绝对化，且不是同构
- 只重复本题答案换个说法 → 没有换层

### 再补几条可迁移原则（批改/展开时可用）

- 快照/版本管读一致，锁管写冲突与范围保护——很多「并发 + 一致性」问题同构。
- case 题：少点名产品，多写「要不要稳定视图 / 读写并发 / 付不付得起膨胀与 GC」。
- 「不该上 MVCC」≠「热点业务」；热点仍可跑在带 MVCC 的库上，靠当前读与锁；不选/慎用应对准 cost（膨胀、GC、纯乐观 abort 爆炸）或场景根本不需要快照事务。
