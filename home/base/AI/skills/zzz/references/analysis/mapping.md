# mapping — 异层同构

**是什么：** 找到与对象 **同一套控制结构** 的另一端，并写出 **步骤或判定的一一对应**，用来 **迁移理解与动作**（结构类比 / 同构启发式，不是演绎必然真）。

**不是：** 目录邻接、depends-on、「和 X 有关」、生活段子（→ `analogy`）、规范↔实现、原语↔使用者、调用栈上下游冒充同构、**廉价还原**（「XX 不就是 YY」——只有标签等价、无步骤环、无差分）。

**纪律：** map 为了迁移动作，**不是**为了结束好奇。先 Q-iso 对齐，再写清 **继承 / 新变量 / 失效点**；没有差分的「不就是」= 降噪，不是理解。
**两拍：** 默认 **拍 A=对齐**（单次 map）；仅在触发时 **拍 B=抓手环**（多 map → 抽主轴/问题型 → 候选再回炉）。单次 map ≠ 已完成归纳；抽抓手才是跨例收束。

本 atom 可由 `/zzz mapping` 单独调用，或由 `/zzz recall` 在用户确认【mapping】后以 **sub-agent** 调用。

**规则全部写在本文；不依赖任何外部盘点文件或库存路径。**

---

## 用法 workflow（深入学某技术时怎么用）

### 总览

```text
0 够用理解（spine） → 1 拍A 单次 map → 2 自检
    →（可选）3 mapping-check → 4 再 map 1～2 对端
    →（≥2 同轴 ok）5 拍B 抓手 → 6 候选再拍A
    →（可选）7 落库存表    // 默认不做
```

**不是**「有点感觉就 `/zzz mapping`，完事必 `/zzz mapping-check`」。
**是**「先有可对齐的控制结构 → 默认只拍 A → check 按需 → 多例再抓手」。

### 阶段 0 — 前置（mapping 之前）

在调用本 atom 前，用户/对话里应已有 **一句控制结构 spine**（读什么、判什么、写什么、失败怎么办）。来源可以是：已读文档、`/zzz recall` 批改后的 gap、`/zzz 3w3h`/`brk` 等——**不强制**某条命令，但 **禁止** 对「只有名词、无步骤」的主题硬 map。

**推进 hint（阶段 0 完）：**
`next: 用一句话写出本题控制环，再 /zzz mapping；对端可指定或让模型提案 1 个 cross。`

### 阶段 1 — 拍 A（默认主路径）

```text
/zzz mapping
topic: <技术/机制>
（可选）对端: <另一层> | 请提案 1 个 cross 对端
只要拍 A；禁止落盘。
```

输出：§4.1「对齐」+ `### self-check` + **`### next`（推进 hint，必给）**。

**推进 hint（拍 A ok 后，模型必须在 artifact 末给出，用户选一条）：**

| 条件 | 建议 next |
|------|-----------|
| 差分闸虚、score 不稳、自检有 no | `/zzz mapping-check`（贴上全文）→ 按 must_fix 再 map |
| 自检全 yes 且想加深 | 再 `/zzz mapping` 换 **另一个对端**（优先 cross；或 instance 扩簇） |
| 已有 ≥2 同轴 ok | `/zzz mapping` 并写明 **请开拍 B 抽抓手** |
| 只想助记 | `/zzz analogy`（与 mapping 分职，非必须） |
| 默认 | **停**；消化 失效点 / 负迁移，勿连打 check |

### 阶段 2 — mapping-check（**按需**，非每步必跑）

**要跑：** 改过 mapping 契约后的回归；score≥4 想当锚点；自检存疑；准备落盘前。
**可跳：** 自检扎实的日常拍 A；纯探索草稿。

```text
/zzz mapping-check
scope: A | A+B
（粘贴完整 mapping 输出）
```

**推进 hint（check 后）：**
- `fail` → 按 must_fix 再 `/zzz mapping`，**不要**先抽抓手
- `pass` → 回到阶段 1 表：再 map 对端 / 拍 B / 停

### 阶段 3 — 拍 B 抓手环（可选）

触发见 §4.4。用户须在指令里写清「请拍 B」或「抽抓手」，避免误开。

**推进 hint（拍 B 后）：**
- 对 **每个** candidate：单独再 `/zzz mapping` 拍 A（或标 skipped）
- 反例 → 改 handle，禁止硬塞
- 需要归档 → 用户明确「写入库存表」才落盘（默认不落）

### 阶段 4 — 与 recall 的关系

| 场景 | 怎么做 |
|------|--------|
| 闭卷练 + 偶尔 map | `/zzz recall` → 确认【mapping】→ **只拍 A、不落盘**；父 agent 验收字段 |
| 系统做迁移/抓手 | **直接 `/zzz mapping`**（不必先 recall） |
| recall 后还要抓手 | 用户追加「请拍 B」；仍不落盘 |

### 常见误用

| 误用 | 应改 |
|------|------|
| 无 spine 就 map | 先阶段 0 |
| 每次 map 后强制 check | 按需；信自检则停 |
| 一条 map 就拍 B | ≥2 同轴 ok 或用户明确要 |
| candidate 当已学会 | 必须再拍 A |
| 「不就是 YY」当 map | 假 maps；补步骤+差分 |

## 0. 两问（必须先答）

| 问 | 含义 | 失败则 |
|----|------|--------|
| **Q-iso（主）** | 同一套控制结构？能否 **≥3 步** 一一对应（须含判定/状态转移/失败分支，禁止空「开始-中间-结束」）？ | 不写 mapping |
| **Q-layer（辅）** | **A cross** / **B instance** / **拒绝类**？ | 拒绝类 → 硬拒绝；B → valid，score 从严自判 |

- 同目录 ≠ 拒绝；同目录也可 Q-iso 成立（秒杀↔抢红包）。
- A → `layer_kind: cross`；B → `layer_kind: instance`。

---

## 1. 层关系

### A — cross（跨机制层）

问题域或运行时角色明显不同。例：MVCC ↔ 业务 version 乐观更新；TCP CC ↔ 限流熔断；list-watch ↔ reactor；幂等锁路径 ↔ `SELECT FOR UPDATE`+version。

### B — instance（同机制实例簇，valid）

同一控制环、不同业务/产品皮。例：秒杀 CAS ↔ 抢红包 ↔ 抽奖；MySQL 主从 ↔ Redis 主从（须写清与 quorum 差异）。

必须：`layer_kind: instance`；**score 自判、无默认分**；`boundary` 写清只对齐哪条环。

### 拒绝类

见 §5 毒码。不写 active score 充数。

### 抓手：秒杀 ↔ 抢红包

- Q-iso 过：读有界量 → 判可分配 → 原子扣减 → 冲突重试/结束 → **valid item**。
- layer：instance；禁止扩成整产品互映（P）；禁止与悲观幂等轴同表硬套（毒码 C）。

---

## 2. 四问验收

1. ≥3 步可对齐，且含判定或失败/终止语义
2. 去掉产品专名后仍能讲通
3. 是「使用/实现/调用」还是「重演控制逻辑」？前三者 → D/I/K
4. 是否单主轴？多机制 → P

对齐之后仍须过 **差分闸**（§4.1 的 继承/新变量/失效点）：只有「同」、零新变量 → 压分或不合格（防「不就是」躺平）。

---

## 3. topic / qs

| 层 | 做 | 不做 |
|----|----|------|
| topic | 整体主轴一句 + 对应 | 不要十个无关域 |
| qs | 挂在已选 topic 轴上逐步对应 | 禁止 qs 另起整域 mapping |

**qs-map 质量规范：** 默认填充 **≥2 对** 实质问题对应（本题疑惑 ↔ 对端等价问法），而非简单写 `none`。仅当 topic 已单轴完全展开、无额外问题可映射时才写 `none`。问题对应应瞄准控制环中的判定/分支/边界条件（如「链路是否拥塞？↔ 服务是否过载？」），而非产品功能罗列。

无 topic 上下文时先补「本题所属结构」一行。

## 4. 输出

### 4.1 会话 artifact（默认；**recall 只走这一轨**）

**注意两问确认段：** artifact 中 **必须** 在 `### 对齐` 前显式列出 `### 两问确认` 小节（见下方模板），写明 Q-iso pass/fail 理由和 Q-layer 判定结果。禁止跳过直接写对齐。

**可读性优先：** 用 Markdown 小标题 + 短列表 + 步骤编号；**禁止**把全部字段塞进一个巨大 `topic-map:` / YAML 墙（难扫读）。字段仍须齐全，用加粗标签行即可。

**Q-layer：** cross | instance | reject

**差分闸（anti「XX 不就是 YY」）：**

| 条件 | 要求 |
|------|------|
| 凡 `status: ok` | **继承、新变量、失效点** 三格都要有（机会或动作可选） |
| `layer_kind: instance` | **新变量、失效点** 禁止敷衍；皮不同必须写出操作/语义差 |
| `score >= 4` | **新变量或失效点** 至少一格有实质内容（不能双「无」） |
| 仅有主轴相同、新变量空洞 | **压分**（通常 ≤2）或不合格 |
| 只有命名等价、无步骤环 | **拒绝**（见不合格 / 近 S），不是低分 valid |

- **recall / 未要求落盘：** 只输出上述结构，**禁止**写任何文件、禁止改 data/gh、禁止写 `*.mapping.table.yml`。
- skipped：原因即可，无 score、无差分格。
- 未触发拍 B 时 **整节「抓手环」省略**（不要空壳标题）。
- `status: ok` 时 **必须**有 `### self-check` 表与 **`### next` 推进 hint**（1～3 条，见文首「用法 workflow」）。
- 判卷/回归用 `/zzz mapping-check`（只验不写；**非**每步必跑）。

### 4.2 矩阵形态（仅用户明确要求落库存时）

- 一轴一表；row = 各方（**每个 `name` 一行**）；列从主轴派生。
- **每个 active `name` 一行一个 `score`**（整数 1–5）：表示该极与本表主轴对齐的可信度；**禁止**整表共用一个 score。
- 主体行也要 score（相对本轴自洽度 / 作轴锚的硬度，自判）。
- 假项：注释整段 item，首行写毒码；不删文件。
- 未要求落盘则 **整节不执行**。

### 4.3 `score`（1–5，严格，无默认）

**含义：** 本条/本行 mapping 的 Q-iso 可信度。
**不是：** gh 实用分、recall 答题 0/1/2、技术重要度。

| 分 | 含义 |
|----|------|
| 5 | canonical：cross、四问全过、几乎无裂缝 |
| 4 | cross 稳，可有轻 boundary |
| 3 | 成立但有界：instance / 半轴 / 明显裂缝；boundary 必读 |
| 2 | 弱，慎作锚点 |
| 1 | 极弱；优先 skipped/注释 |

纪律：

1. 每个 ok 的 topic-map **以及** 每个库存 active name **必填 score**；禁止省略。
2. **禁止默认填 3**（或任何固定分）；据证据自判，吃不准压分。
3. 5 极稀缺；instance 原则上到不了 5。
4. 半轴通常 ≤3。
5. 毒码命中 → 拒绝，不用 score:1 冒充 valid。
6. `score >= 4` 时加一行 **score依据**（一句，说明为何不是 ±1）。
7. 与 gh 实用 score 禁止默认相等。
8. 差分闸未过（无实质新变量且高分、或 instance 无失效点）→ **压分**，不得装 canonical。

### 4.4 抓手环（可选第二拍）

**定性（一句）：** 单次 map = 结构对齐；**抽抓手 = 从多条 valid map 收束问题型**（结构归纳）；**套抓手 = 可错迁移**（生成候选，不是证明）。抓的是 **控制结构**，不是标签/品类特征。

**仅当触发（满足任一）才跑；禁止每次 map 默认开跑：**

1. 用户明确要「抽主轴 / 抓手 / 问题型 / 再铺 case / 学 1 当 N」
2. 本轮或可见上下文已有 **≥2** 条同轴、`status: ok` 的 map（如秒杀 + 红包）
3. 用户直接给出 instance 簇并要求收束

**硬规则：**

- 拍 A 未过（Q-iso 失败）→ **禁止**拍 B
- 抓手必须来自 **≥2** 个已 ok 的 map，禁止从一句「不就是」起飞
- `candidates` **不是** valid map；每个候选须再跑拍 A，或标 `status: candidate` 并写「待 Q-iso」
- 候选变 ok → 仍过差分闸；出现反例 → **改 handle 或缩小适用范围**，禁止硬塞
- recall 默认只拍 A；用户加要抓手/更多 case 时才拍 B，**仍禁止落盘**

**拍 B 输出：** 使用 §4.1 中「### 抓手环」模板（handle 列表 + candidates **表** + next 列表），接在拍 A 后；不另起难扫的纯 YAML 墙。

**坏环（禁止）：** 抓手过宽 → 什么都像 → 虚高分 → 更宽抓手。
**好环：** 对齐 → 概括(handle) → 候选 → 再对齐+差分 → 修正 handle。

## 5. 毒码硬拒绝（D / I / K / P / C / S）

| 码 | 含义 | 例 |
|----|------|-----|
| D | 依赖原语，无独立环 | hash ↔ Git |
| I | 实现/算法实例假对端 | Raft ↔ etcd-raft；BBR 当 TCP-CC 对端 row |
| K | 栈上下游 | list-watch ↔ etcd Watch |
| P | 拼盘 | 熔断+DAG 一行 |
| C | 硬套轴/列 | CAS 表塞悲观幂等 |
| S | 无环邻接 | 「见其它 topic」 |

S ≠ 同目录。同目录且 Q-iso 过 → instance。

**廉价还原**（无步骤、无差分的「XX 不就是 YY」）按 **S** 或直接不合格处理，不要打成 valid map。

## 6. 合格 / 不合格（密度校准）

### 合格（应模仿）

**MVCC 轴**（快照/版本管读 + 锁或校验管写）：

1. MVCC 可见性 ↔ 业务乐观「读 version→判→更新→冲突重试」（cross；宜高分）
2. 快照读 ↔ git 历史视图（cross）
3. FOR UPDATE/间隙 ↔ protected branch（cross；半轴，boundary，分通常 ≤4）
4. MVOCC/MV2PL ↔ 乐观/悲观（delay vs abort）
5. CC delay/abort ↔ 线程阻塞 vs 失败重试
6. 多版本需求 ↔ 协作文档/COW（需求语言，禁品类绝对化）
7. 应用层 version（boundary：非完整库 MVCC）
8. 秒杀 CAS ↔ 抢红包（instance，valid；只扣减环；**须**写新变量/失效点，如拆包、终态、是否预减库存）

**编排轴（补密度，防只会 MVCC）：**
带门控的闭环 `decide→authorize→effect→observe→re-decide`，权威状态只认已执行结果（如 tool_result / 已提交状态），不认口头声称 —— 可与工作流门控、admission、网关鉴权对照（cross）。例：继承=反馈闭环；新变量=执行主体为模型、工具副作用、只信 tool_result；失效点=把「模型声称已执行」当事实。

### 不合格

目录邻接；品类绝对化；无换层；qs 另起炉灶；P/D/I/K/C；无 score 的 ok 输出；固定 score:3 无依据；**「XX 不就是 YY」无步骤环**；**对齐后零新变量还标高分**；instance 无失效点/操作差；**未触发却灌 handle/candidates**；**从 0～1 条 map 伪造抓手**；**把 candidate 直接当 ok map**。

## 7. 可迁移

- 少点名产品，多写需求：稳定视图 / 读写并发 / 膨胀与 GC / 有界资源热路径。
- 负迁移：instance 不能推出「已打通另一整层」；半轴不能推全轴。
- **先 map 再 delta：** 继承用于省认知，新变量/失效点用于反廉价还原；机会或动作把 map 接到「做什么」。
- **多 map 再抓手：** 学的是 **1 条控制环/问题型**，不是 N 份产品细节免单；用抓手生成候选后必须回炉 Q-iso+差分。
- 教学锚点优先高分 cross 且差分闸已过；instance / handle 作对照与收束。
