# mapping — 异层同构

**是什么：** 在另一抽象层（业务代码 / 应用协议 / VCS / 运行时调度…）找到与对象 **同一套控制结构**，并写出 **步骤或判定的一一对应**，用来迁移理解。

**不是：** 目录邻接、depends-on 图谱、「和 X 有关」词条列表、生活段子（段子走 `analogy`）。

本 atom 通常由 `/zzz recall` 在用户**明确同意【mapping】**后以 **sub-agent** 调用。也可单独 `/zzz mapping`。

---

## 分层（必须遵守）

| 层 | 做什么 | 不做什么 |
|----|--------|----------|
| **topic 级** | 先给出**整体**控制结构同构（一句话 + 主对应轴） | 不要一上来拆成十个无关域 |
| **qs / 本题级** | 在**已选 topic 同构轴**上，做机制/步骤一一对应 | **禁止**为本题另起一套与 topic 无关的整域 mapping |

类比：先整体类比，再映射具体细节与 mechanism——**mapping 同序**。

若只有单题、无 topic 上下文：先补一行「本题所属结构」再写步骤对应。

---

## 输出格式

```text
## artifact
step: mapping
status: ok | skipped

topic-map:
  本题/本 topic 结构：…
  另一层：…
  主轴：… ↔ …
  可迁移判断：…

qs-map:   # 若本轮有具体题；否则写 none
  - （本题）… ↔ （另一层）…
  - …
```

未确认或无可映射结构：`status: skipped` + 原因。

## 合格 / 不合格（校准密度）

### 合格（应模仿）

以 **MVCC** 为同一 case（topic 轴 =「快照/版本管读 + 锁/校验管写」）：

1. **MVCC 可见性 ↔ 业务「一锁二判三更新」**（canonical）
   - 本题：版本链 + ReadView；用 trx_id 与高低水位比较决定可见版本；提交前冲突则失败。
   - 另一层：高并发业务先读 version → 判断 → 再更新；失败则 spin / for 重试。
   - 同构：先基于某一视图做判断，再提交变更；冲突则重来——不是「都和并发有关」。

2. **普通 SELECT（快照读）↔ git log / checkout 看历史提交**
   - 已有提交视图不被后来 push 改掉 ≈ 快照内多次读稳定。
   - 可迁移：版本/快照管 **读一致**。

3. **`SELECT … FOR UPDATE` + 间隙/临键 ↔ protected branch / MR 门禁**
   - 锁范围、防「范围内新插入」≈ 禁止往保护分支直接塞新提交。
   - 可迁移：锁管 **写与范围保护**；与快照读分职。
   - 注意：git 没有真 gap lock，类比到「保护范围」即可。

4. **MVOCC vs MV2PL ↔ 乐观锁 vs 悲观锁**
   - 更乐观：先做事、提交 validation，失败 **abort**。
   - 更悲观：先锁，**delay** 等待；死锁则 abort 一方。
   - 可迁移：delay 谱系 vs abort 谱系。

5. **CC 的 delay/abort ↔ 线程同步里阻塞 vs 失败重试**
   - 调度语义同构，不是「CC 和操作系统都是系统软件」。

6. **何时需要多版本事务语义 ↔ 协作文档快照 / COW**
   - 需要：多读者要稳定视图、读写并发。
   - 不需要：单写者队列、只追加日志、覆盖写且无事务读。
   - 用 **需求** 说话，不用「凡 KV/文档库都要 MVCC」。

7. **应用层 version 字段**
   - 有一点多版本/乐观并发味道，但是 **应用层**；库仍可能行锁、无经典 MVCC——maps 时分层说清。

### 不合格

- 「maps：和隔离级别有关 / 见 RDB 其它 topic」→ **目录邻接**
- 「凡 NewSQL/缓存都要 MVCC」→ **品类绝对化**，且不是同构
- 只重复本题答案换个说法 → **没有换层**
- topic 说「版本管读」，qs 突然整段映射到无关的「DNS TTL」且无主轴承接 → **qs 另起炉灶**
- 「Redis 持久化像 A，Kafka 分区像 B」拼在一道 MVCC 题下 → **多工具机制假 mapping**

---

## 可迁移原则（批改/展开可用）

- 快照/版本管读一致，锁管写冲突与范围保护——很多「并发 + 一致性」问题同构。
- case 题：少点名产品，多写「要不要稳定视图 / 读写并发 / 付不付得起膨胀与 GC」。
- 「不该上 MVCC」≠「热点业务」；热点仍可跑在带 MVCC 的库上，靠当前读与锁；不选/慎用应对准 cost 或场景根本不需要快照事务。
