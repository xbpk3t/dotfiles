---
name: write-prpt
role: atom
description: 编写/重构 prompt skill（SKILL.md 或 zzz references 子 prompt）；先对齐信息再开工，产出符合 zzz 模板族的完整 md 文件
trigger:
  - manual
---


**是什么：** 根据用户需求，编写或重构一个 prompt（SKILL.md 或 zzz references 下的子 prompt），产出**符合 zzz 模板族**的完整 markdown 文件，可直接放入 `references/` 或作为独立 skill 使用。

**不是：** 优化已有 prompt 的性能（那是 SkillOpt / skill-creator 的事）；编写完整 skill 的 harness（zzz.nu、gen-aliases.nu 等）；项目管理（那是 issue 的事）。

---

## 工作流

```
/zzz write-prpt <目标>
  → Gate A 初判：该不该写？（强制显式输出；信息不足则标记，进 Gate 1）
  → Gate 1：信息量充分吗？（不充分 → drill me，规则已内联）
  → Gate A 终判：信息充分后最终裁决该不该写（强制显式输出）
  → 执行写作（5 层结构 + 输出模板）
  → Gate 3：语言适配？（默认中文）
  → 输出完整 md 文件（不自动落盘，询问）
```

---

## Gate A：该不该写？（合并判断，两次执行，强制显式输出）

**该不该写** 是唯一判断，不再拆分 Gate 0 / Gate 2。判断依据 = **值不值得写成 skill**（类型判断已并入，见下）。

**⚠️ 强制显式输出：** 无论信息是否充分，**你的回答里必须显式写出 Gate A 判断**（该写 / 不该写 / 需 drill，+ 依据），**禁止**自己默默判断后默认执行。否则用户无法知道你执行到哪步。输出格式：

```text
## Gate A 判断
verdict: 该写 | 不该写 | 需 drill
依据: <一句话理由>
```

### 判断依据（"该不该写" = 值不值得 skill 化）

| 类型 | 适合 skill? | 理由 |
|------|------------|------|
| 固定工作流（多步骤、有顺序） | ✅ 该写 | 可测试、可复用 |
| 格式转换 / 数据提取 | ✅ 该写 | 输出可验证 |
| 决策辅助 / 评估 | ✅ 该写 | 有明确输出结构 |
| 主观创作（风格、散文） | ⚠️ 边缘 | 可写但难验证，评估方式不同 |
| 一次性脚本 / 临时需求 | ❌ 不该写 | 不值得固化 |

**其它不该写的信号：**
- 已有同功能的 prompt 存在（先查 `references/` 和 `~/.claude/skills/`）
- 只是临时需求，不值得固化成 skill
- 目标太模糊，无法确定做什么（但仍需 drill 才能定）

### 初判（进入 Gate 1 之前）

在开始 drill me 之前，先基于已有信息快速判断，**必须显式输出初判结论**：

- **信息已足 + 明显不该写** → 直接挡（不浪费 drill me）
- **信息已足 + 该写** → 显式输出"该写"，**跳到终判确认**（跳过 Gate 1 drill，因为信息已足）
- **信息不足** → 显式输出"需 drill"，标记"待 Gate 1 一并问"，进入 Gate 1 drill me

**初判的意义**：信息充分时直接挡掉"明显不该写"的（已有同功能 / 临时需求），不浪费 drill me 追问。**但初判必须显式输出，不能默默决定。**

### 终判（Gate 1 drill 完成后，或信息已足时跳过 Gate 1 直接到这里）

drill me 问完信息充分后（或信息一开始就足），**重新判断一次**该不该写，**同样必须显式输出终判结论**：

- **不该写** → 停（说明理由：已有同功能 / 临时需求 / 不适合 skill 化）
- **该写** → 进入写作

**终判的意义**：无论信息是否一开始就充分，都必须走到终判这一步**最终裁决**，防初判误判（比如 drill 后发现其实是已有功能的重复）。**信息充足时初判"该写"→ 直接跳到终判确认，不能跳过终判直接写作。**

### 初判 vs 终判的关系

| | 初判 | 终判 |
|---|------|------|
| 时机 | Gate 1 之前 | Gate 1 之后（或信息已足时直接到此） |
| 信息量 | 已有信息（可能不足） | drill 后充分信息 |
| 作用 | 挡掉明显不该写的 | 最终裁决是否真的该写 |
| 是否强制输出 | **必须** | **必须** |
| 关系 | 初判是**快速过滤**，终判是**最终裁决** | |

### 为什么必须显式输出

AI 默认倾向"用户需求明确 → 直接写"，会默默跳过 Gate A。强制显式输出有两个作用：
1. **用户可追踪**：知道 AI 执行到哪步（Gate A 初判 → Gate 1 drill → Gate A 终判 → 写作）
2. **强制 AI 判断**：即使信息充分，也必须明确说"该写"才能继续，防止跳过流程

## 链式调用规则（元规则）

**需要链式调用其它 prpt 时，必须引用该 prpt 的 md 文件本身**（相对链接，如 `[choose.md](choose.md)`），并按文件的完整格式执行；**禁止**只转述其规则、只提名字、或把规则抄进本文件。

理由：zzz 的 prompt 是单一事实源（标准唯一来源）。转述会产生漂移（措辞不一致、规则过时），引用 md 实体则保证被调用方始终按最新版执行。本规则适用于本文件内所有对其它 prpt 的引用（如 Gate 1 的 drill → choose.md）。

## Gate 1：信息量充分吗？（不足 → drill me）

**规则：** 不存在"有了名字+目标就直接开工"的 case。**信息量不够就直接 drill me**（反问规则已内联，见下），判断信息量足够后才开工。

**信息充分的判据（至少满足 3 条）：**
1. 明确的目标 prompt 用途（做什么）
2. 触发场景（什么时候用）
3. 输出形态（产出什么格式）
4. 边界（不做什么）
5. 受众 / 使用频率

**drill me 规则：** 需要反问用户时，**直接引用 [choose.md](choose.md) 这个 md 文件本身并按它的格式执行**（链式调用须引用 md 实体，见下方规则），不要只转述其规则。其要点：
- 禁止开放性问题；必须转化为选择题（每个问题 2-3 个选项）
- 最多 3 个选择题后必须进入终判
- 若探索已能推断答案，不提问

## 执行写作（5 层结构）

按 zzz 模板族输出一个完整 md 文件。骨架如下（**必须使用**，不可跳过核心节）：

```markdown
---
name: <stem>
role: atom | composite
description: <功能一句话>；<边界/依赖>
trigger:
  - manual
pipeline: [list]            # 仅 composite；soft 依赖只写 body
---

## 定义（是什么/不是什么）
**是什么：** <一句话职责边界>
**不是：** <排除项（那是 <other>）>    # 归属转移必须写清楚

## 入口 gate（先答后做）
| 问 | 含义 | 失败则 |
|----|------|--------|
| Q1 | <判定> | <不进入> |

## 硬约束（编号，可验证）
1. **必须** <可判真伪>
2. **禁止** <行为>
3. 默认 <X>；仅当 <触发> 才 <Y>

## 输出契约（必须使用）
````text
## artifact
step: <name>
status: ok | skipped
<字段…>
````
<字段语义表 + 数量要求 + 格式禁令>

## self-check（输出前必过）
| # | 项 | yes/no |
|---|-----|--------|

## next（推进 hint，必给）
| 条件 | 建议 next |
|------|-----------|
| … | /zzz <other>（…） |
| 默认 | 停 |

## 禁止 / 边界
- 禁止副作用写盘（产物只在对话；用户明确指定路径除外）
```

**说明：**
- **不要 H1（`# <name>`）**：新生成的 prompt 从 `##` 开始（精简）
- **`<other>` 填 zzz 里已有的其它 prompt 名**（如 mapping / vs / brk / explore），用于"归属转移"——声明这个 prompt 不做什么、那是谁的事
- **trigger 是数组**：默认 `manual`（手动 `/zzz <name>`）；仅当有周期/事件触发时才加别的值（如 `dagu` / `recurring`），给你自己看
- **description 不需要触发条件词**：zzz 是 prompt 合集，靠 `/zzz <name>` 手动路由，所以 description 只写功能 + 边界（如 explore: "替代方案探索；seed-aware"）
- 各节按需裁剪：简单 atom 可省 self-check；composite 加 pipeline 编排节

---

## Gate 3：语言适配？

- 默认输出**中文**（zzz 全部是中文 prompt）
- 若用户明确指定 target 语言（如"用英文写"），则输出对应语言
- 若有对象 skill / 语言约束，遵循它

---

## 输出与落盘

- **输出**：完整 md 文件内容（对话中呈现）
- **不自动落盘**：默认只在对话输出，询问用户是否写入
- **落盘路径**（用户确认后）：`$HOME/.claude/skills/zzz/references/`（测试 [即时可路由]），测完整合回 dotfiles

---

## 收尾

输出完成后，提示用户可选项：
- 跑 skill-creator evals 验证（若输出可断言）
- 跑 SkillOpt 训练优化（若需要）
- `nu gen-aliases.nu`（若写入 zzz references）
